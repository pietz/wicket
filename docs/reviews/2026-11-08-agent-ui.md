# Agent output as native UI (2026-11-08)

The question: how should a Run Agent reply become native Wicket UI (for example, recent files as real rows), so that it is flexible for rich UI, keeps Wicket in control, and is unambiguous for the agent? Three independent advisors answered: GPT-6.1 Sol (research), GPT-6 Astra and Claude Fable 5.1. Astra and Fable did not see the lead's lean.

## Agreed by all three

- **One vocabulary:** reuse the extension protocol's screens (answer, list, detail). No agent-only format.
- **Wicket draws everything:** the agent sends data. Wicket derives icons and adds its own file actions (Reveal in Finder, Copy Path).
- **Agent screens are untrusted:** share the presentation types with extensions, never their authority. Version 1 presents results only: open (restricted like links in answers), reveal, copy and navigation. No `run`, approvals, enabling or automatic actions. The action panel names the real target.
- **No markdown heuristics:** promoting ordinary links to rows is unpredictable for the model.
- **The extension contract is sound:** JSON-RPC over stdio, cancellation, strict decoding, revision-bound actions. It gains from this work; it needs no redesign.
- **Defer:** grids, forms, component trees, streaming patches, an MCP presentation tool. Grow the vocabulary one semantic case at a time, advertising only what's supported.
- **On failure,** keep the prose with a notice. Never rerun an acting task to repair its presentation.

## The split: how the JSON leaves the agent

- **The harness's structured output (Sol, Astra).** Codex 0.167 has `turn/start.outputSchema`, set per turn and enforced by constrained decoding. Claude Code 2.1.319 has `--json-schema`: a `StructuredOutput` tool that is validated and retried, with the result in `result.structured_output`. Every reply has one required shape, and prose lives in `detail.markdown`. Traps: ClaudeTranscript must not count `StructuredOutput` as acting; retries can run out; the provider schemas need an object root and required fields.
- **A fenced ```wicket block in the markdown reply (Fable).** The adapters don't change, the prose stays prose, and the same block becomes usable in extension details. Risks: the fence is optional and can be forgotten, quoted examples are ambiguous, and malformed JSON can only be reported, not retried.

## Rows inside the page, or a list with an introduction

- **Fable:** embed rows in the answer page, which needs keyboard selection inside a scrolling page.
- **Sol, Astra:** the reply is a list screen with an optional markdown introduction, added to the shared list contract.

## Lead's recommendation

**Structured output, with a list that can carry an introduction.** Two of three advisors chose it, and it scores best on "unambiguous". The constraint lives in the harness, not in a convention the model may forget. Prose-only answers are simply `detail`. A list with an introduction reuses the existing list views and selection, which is smaller than selection inside a page.

Before building, run a spike that proves both CLIs live: tool use, approvals, Follow Up with resume, a refusal, and missing structured output. If Claude's path fails there, the fenced block is the fallback design.

## Round 2: design, challenge, spike

- **Design (Fable):** docs/reviews/2026-11-08-ui-system-design.md. Semantic components only. One screen per reply (answer, list, detail). Lists get an intro and sections. `file` and `url` subjects let Wicket derive the icon, actions and Quick Look. Authority profiles. v2: grid, show, reply rows, forms.
- **Spike:** docs/reviews/2026-11-08-structured-output-spike.md. The harness schema holds live for both CLIs: tools, approvals, resume, failures. The schema alone doesn't steer small models, so the agent.md rules matter.
- **Challenge (Astra):** keep the core (shared vocabulary, host rendering, harness schema, present-only, no styling). But:
  - Allow bounded composition: a summary, labelled facts and one collection in a single reply, with no hard clip.
  - Leave the door open for charts, images, tables and timelines.
  - Choose by intent: a list even for one result.
  - Define subject identity: duplicate names, missing files, one canonical form.
  - Carry authority through navigation and dispatch, not just decode.
  - Keep host controls (Follow Up, Copy) at screen level on lists.
  - Replace the schema-rewrite sketch with a tested projection: recursion, nullable optionals versus the decoder, draft-07 for Claude.
  - Judge by task success, adding edge cases (empty, single, duplicates, deleted files, VoiceOver).

**Lead's synthesis:** Fable's structure plus Astra's corrections.
- A list becomes the composed reply: an expandable summary, optional facts, then the rows, which covers "three invoices total €420, one overdue".
- detail stays for prose.
- answer stays for a scalar.
- Richer kinds (grid, chart, image) are on the roadmap as tiers, each added when a real use case shows up, not forbidden.
