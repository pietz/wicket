# AI-native direction: advisor verdicts (2026-11-08)

Three GPT advisors, none told the lead's view. Input for the owner's decision, not a decision.

**Product (Sol):** one AI entry; keep plain web search as a fast shortcut; drop Ask/Do as separate rows. Replace plan-and-Run with task-scoped approval (Allow this task / Allow this operation / Cancel), with separate confirmation for deletion, sending, purchases, installs. Pushback: capability is not authorization; a harness's auto mode is not a product policy Wicket can promise.

**Vision (Astra):** "An AI-native launcher turns what you are looking at into something you can do, then lets you keep that ability." Ranked: (1) do this, then Keep as command; (2) the selection as a working object (select text, instruct, Replace selection, refine); (3) edit a command where you use it ("change this command to..."); (4) long jobs you dismiss and pick up on the next summon. Remove Ask/Do/Make as user choices and the universal plan/review/Run ceremony. Challenges the thesis "the model is the compiler, not the runtime" as too restrictive: compile stable mechanics, use agents for judgment. Build next: selected text, instruction, replacement, Keep as command.

**Technical (Sol):** harness-decides is feasible.
- Codex app-server already sends `item/commandExecution/requestApproval` and `item/fileChange/requestApproval`; the client answers accept / acceptForSession / decline / cancel. Wicket's adapter forces `approvalPolicy: "never"` and refuses every request (`CodexTranscript.swift`).
- Claude Code loads the user's settings (`~/.claude/settings.json`) unless restricted; permission prompts reach a client through stream-json `can_use_tool` control requests or `--permission-prompt-tool`. Wicket forces `--permission-prompts none` and `--restricted` (ignores user settings) and closes stdin.
- Smallest change: one cancellable approval channel through `AgentProcess` into the job UI; Codex first, then Claude's bridge. Do's script path has to become an acting agent run; flags alone don't remove the Run gate.
- Risks: auto-approved actions never reach Wicket; unrestricted runs bring back the user's hooks and MCP servers in any folder. Not verified: a live approval round trip.
