# Simplification reviews (2026-11-08, three GPT-6.1 Sol reviewers, read-only)

The owner found the codebase larger than expected: about 19,400 production and 13,100 test lines. Three areas were reviewed for a minimal but solid design.

## Extension system (5,900 lines, target 3,000 to 3,400)

**Cut:**
- root mode;
- persistent JSON-RPC sessions, retries and `repeatable`; replaced by one process per invocation, with JSON in and JSON out once;
- the sandboxed fixture checker; replaced by a static `wicket check`, and real testing stays with `wicket run`;
- rollback and earlier revisions;
- Wicket-managed uv (dependencies are vendored instead);
- capabilities.

**Keep:**
- one approved snapshot plus the review candidate;
- UI-only approval tied to the snapshot that was shown;
- secrets;
- `ProcessTree` and the login PATH;
- strict decoding;
- run history and Fix and Change with Agent.

**Fix:** `wicket run` returns success on an error response.

## Palette (5,850 lines, target 3,600 to 4,100 plus the markup renderer)

- **Merge** `Frame` and `ScreenFrame`, and make one observable owner (session plus model).
- **Push command frames immediately,** with no separate opening state.
- **Invalidate on a revision change** instead of replaying automatically.
- **Fixed-height documents** instead of content measurement; lists keep the whole-row sizing.
- **Drop** the legacy usage migration, and trim the comments.

**Keep:** cancellation, the generation checks, `ActionTarget` and authority, the registry and dispatcher, ranking, and the system-effects safeguards.

## AI and settings (4,080 lines, target 2,700 to 3,000)

**Cut:**
- answer-only mode and `wicket agent ask`;
- the four Wicket permission levels and their store, in favour of the harness's own policy (owner);
- Allow for Session and the rewriting of Claude's session-grant suggestions;
- activity strings, usage accounting and "acted" inference;
- the streaming setting and `Throttle`: whole messages only (owner);
- the automatic fresh retry after a failed resume (an explicit fresh run is offered instead);
- renamed-key and Apple compatibility code.

**Keep:**
- the model, effort and speed pickers (owner);
- both adapters, `ProcessTree`, approval tokens and harness session resume;
- readiness checks and the settings mechanics.

## Lead's decisions

- **Extensions:** all four recommendations: no root mode, a static check, no rollback, per-run processes with vendored dependencies.
- **Palette:** all three: fixed-height documents, a brief loading state for commands that only have an effect, an explicit rerun after an extension is replaced.
- **AI:** as above, with the owner's three calls.
