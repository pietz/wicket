# Settings

The menu bar icon's menu offers **Settings…** (Cmd+, while Wicket is active), as does typing `settings` in the launcher. **Open Config Folder** is a secondary action. The window is an AppKit toolbar tab controller with native SwiftUI grouped forms, 560 by 480 points of pane content. It keeps its selected tab while open, and closing it returns the app to accessory mode. The main menu provides Cmd+W and Cmd+Q. [SPEC.md](../SPEC.md) has the full rules.

## Tabs

- **General:** shortcut recorder with registration conflict feedback, background transparency (a slider from More readable to More glass; a stored 0.15, the old default, reads as the new default 0.75, so the slider saves 0.16 there), Text size (Small to Larger), launch at login and config-folder access. In the released edition, an Updates section: a switch for automatic checks, the version and **Check for Updates…** (Sparkle; absent in Wicket Dev and outside an app bundle). Launch at login reads `SMAppService.mainApp.status` and is not a config key; pending approval links to Login Items, and registration failures show the macOS error with a note that ad hoc builds may be refused.
- **Voice:** `voice.enabled`, the Microphone picker (Automatic or a named input, stored by UID), microphone permission state and a System Settings link. Permission is read without requesting it, and opening the tab never listens.
- **Agent:** Claude or ChatGPT, model, effort, permission mode, speed and Stream answers. Choices come from what each installed CLI lists, asked without a model call when the tab opens and cached per agent for an hour in `agent-options-claude.json` and `agent-options-codex.json`. Saved values survive a failed listing. Switching agent clears the model, effort, mode and speed of the previous one and keeps unknown fields. An Agent History section says what it keeps, shows the number of saved runs and has Clear History with a confirmation. The runs live in `~/Library/Application Support/app.wicket.Wicket/agent-history.json`, outside the agent's folder: the newest 100 for 30 days, limits that are fixed.
- **Extensions:** a list on the left, Built in (Apps, Files, Clipboard History) and Extensions (the bundled calculator, units and window commands and your own, by name), each with its on/off switch, and Extensions Folder below it. Each switch is a `providers` entry; one without an entry is on, except Clipboard History, which is off until switched on. Results are ranked by match quality, so there is no order to set. The selected one's detail shows its name and description (the manifest's `description`), Show in Finder and, for a bundled extension, **Make It Mine**, which copies its folder into `extensions/`, where your copy replaces the bundled one and you or your agent can change it (it refuses when a folder of that name is there). Then its settings (below) and a hotkey recorder for its command and each of its items. Clipboard History's detail: its hotkey, what it keeps, a hint when macOS would ask before each pasteboard read, the number of saved texts and Clear History with a confirmation. The texts live in `~/Library/Application Support/app.wicket.Wicket/clipboard-history.json`, outside the agent's folder. It keeps the newest 500 texts for 30 days; these limits are fixed.

## Extension settings

A manifest declares `settings` as it declares `arguments`, plus an optional default: `"settings": [{"name": "gap", "placeholder": "Gap (points)", "default": "0"}]`. Settings shows a field per setting, labelled by its placeholder, with the default as its prompt; it saves on Return or when it loses focus, and emptying it brings the default back. Values live in `config.json` under `extensions`, by folder name: `"extensions": {"window": {"gap": "8", "almostMaximize": "85"}}`, strings only. Every request to the extension carries them as `"settings": {…}`, with defaults filled in. The window commands have `gap` (points between a window and the screen's edges and between halves, default 0) and `almostMaximize` (percent of each side, default 90).

## One write path

`config.json` is the single source of truth, with no UserDefaults copy. `ConfigurationFile.edit` is the only way settings are written: it reads the latest bytes, validates them with `Configuration`, patches the JSON object, validates the result and replaces the file atomically. Unknown root, nested and provider-entry fields survive, as does the provider list as written. `ConfigurationStore` publishes the last good configuration and the same `Config: …` problem the launcher shows. An exact-file watcher, including atomic replacement, reloads on outside edits; a second one reloads the agent-options cache. A broken file stays untouched with its last good values visible, editing disabled and the config-folder button and tabs usable; repairing it restores editing live. A failed write shows its own message and leaves the controls usable.

Updates are the exception on purpose: Sparkle's switch lives in Sparkle's user defaults, because it is the app's housekeeping rather than a preference an agent should edit.

## Shortcut recording

Recording uses a local raw-key monitor, so Option combinations and command equivalents survive, and pauses Wicket's global registration. Escape, app deactivation, leaving the pane or closing the window stops it. A replacement is registered before it is saved: a conflict keeps the previous working registration and file value with feedback in Settings, and a failed save restores the previous registration. Command plus a single letter is refused. `HotKeyRegistration.apply` produces the feedback and tests inject fake registration handles.

## Hotkeys for commands

Any row with an address of its own (an extension's command, one of its manifest items such as Window ▸ Left Half, Settings, Agent History, Clipboard History) can get a global hotkey: right-click it, choose **Set Hotkey…** and press the combination, or **Remove Hotkey**. The row shows it at its trailing edge. The panel's recorder follows the rules above: every hotkey of Wicket's, the launcher's included, is paused while either recorder listens, Command plus a single letter is refused, the launcher's shortcut or another binding's is refused, and a replacement is registered before it is saved, so a conflict keeps the working one and the file unchanged. The bindings are `hotkeys` in `config.json`, `[{"keys": "ctrl+option+left", "address": "wicket://window?item=left"}]`, the keys spelled like `hotkey` and one entry per address; an outside edit is applied live and each conflict is reported in the panel's footer without costing the others. Settings ▸ Extensions lists the same addresses for each extension, with a recorder each under the same rules. There are no default bindings.
